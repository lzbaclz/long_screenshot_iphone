# 0.1.6（7）启动恢复修复方案

日期：2026-09-16。用户已明确授权由主代理设计、GPT-6 Astra（high）子代理实施与验证，并由同配置子代理上传新的 TestFlight。方案与记录使用 Markdown，完成已授权工作不再增加审批环节。

## 目标和依据

修复广播面板／应用切换器成为待定首帧后，进入目标页面滚动仍停留在旧单屏的问题。调查证据见 [启动调查](validation/2026-09-16-startup-anchor-investigation.md)：目标帧直接输入可拼接，前置无关画面后失败；全帧三次完全相同是现有候选替换的唯一入口。起拼前暂停恢复又可能禁止替换候选。用户视频不能证明手机内部帧数和暂停回调，因此按可复现缺陷修复并保留验证边界。

拟发布版本为 0.1.6（7）；发布代理须先核对 Apple 当前构建，若构建号已占用则使用更大的下一个号并回填记录。正式 App Store 审核资料、商店素材和现有测试员关系保持各自的既有流程，本次授权为新版 TestFlight。

## 起点恢复规则

1. **保留原始待定图作为兜底，另保留一个有界的新场景候选。** 首次取到系统 UI 不代表已开始拼接。旧候选比对失败后，可暂存最近的新场景灰度和候选 PNG，但这一步不发布为连续内容，也不把任意拒绝帧直接设成可信起点。
2. **优先尝试原起点；再验证新场景相邻帧。** 起拼前，若原起点无法衔接，而新的候选与当前帧通过现有严格的重叠、歧义、固定区域和前景验证，就以这个经过验证的目标候选开始，保留该候选完整首屏和真实新增条带。支持上下两向、固定栏、壁纸、手动区域；不降低现有匹配阈值，不把系统旧图接入正文，不以等待时间证明位移。实现中不得遗漏目前 region／foreground 的早返回分支。
3. **允许局部微小变化的静止候选更新。** 全帧相等可作为快速路径，但不是唯一标准。稳定检测应限制局部差异比例和强度，并检查分布／持续性；不能让任意换页、缓慢漂移或大面积动画伪装成稳定。稳定更新只建立单屏候选，后续长图仍须通过原拼接验证。稀疏采样时，即使不满足稳定采样次数，也可由上一条相邻运动证据起步。
4. **成功写入后的内容不重新定起点。** `hasStarted`／已确认提交后的未知缺口沿用严格拒绝与恢复规则；拒绝帧不进入可信历史。起拼前的候选变化应有可见的开头提示，不能声称未采到的原始起点完整。
5. **存储与资源有界。** 不跨回调保留 CMSampleBuffer／CVPixelBuffer，不积累完整 CGImage 历史。额外候选最多一份灰度和一张临时 PNG；替换、成功、停止、错误及析构需清理。先完成新图写入再替换旧候选，出错保留已落盘兜底。首个提交失败、上限、自然行序及固定栏事务不能退化。

## 生命周期与可观察性

- 只有已经建立连续内容的捕捉，暂停恢复才必须找回先前正文重叠。仅有启动候选时恢复仍处于可换起点状态；连续暂停和已开始后的未知缺口保护保留。两个采集适配器调用相同规则，实验后端不启用。
- 起拼尚未确认时，主应用显示“等待目标内容／请在目标页面缓慢滚动”；一定时间仍无进展时解释当前未确认正文，不立即无条件结束或捏造成功。在别的 App 上不添加非公开浮层；系统捕捉指示照常保留。
- 详情提供足以区分采样不足与匹配拒绝的有界数值诊断：接收视频样本、处理帧、跳过样本、起点替换、最近的起步恢复方式、等待状态；保留现有未衔接、处理耗时和暂停数据。新增持久化字段可选，兼容旧会话。
- “系统入口结束（可能包含手动停止）”与已知 App 手动请求区分。保留旧清单解码与旧原因本地化，避免把系统回调写成“系统杀掉”。中英文界面均补齐。

## 验证和验收

1. 把上一轮临时诊断转为期望成功的原生回归：无关启动帧 → 立即滚动、只停一至两帧、状态角落变化、上下方向、原起点后来重新可匹配。
2. 真实像素验收使用合成公开素材：完整导出不包含启动面板、首尾与行序正确、固定栏一次、prepend／反转正确、壁纸与手动区域兼容。加入至少原生手机比例／分辨率的启动切换场景。
3. 对抗验证：持续无关帧不生成假长图、无可靠重叠不跨接、已起拼后的未知缺口不换起点、暂停前后不同策略、旋转／尺寸变化、候选与首个提交失败回滚、临时资源清理。
4. 必要验证包括 Swift 核心回归、iOS 原生管线／存储／生命周期测试、相关模拟器真实滚动与 UI 中英文诊断／保存分享检查。已通过的同源码检查不无故重复；本轮不增加自动 CI 或自动发布任务。
5. 核心代理使用独立 DerivedData 和专用模拟器 Longlet-Beta2；界面代理先编译和做静态校验，模拟器测试需与主代理协调，避免同时控制同一设备或改工程配置。发布代理在最终验证前只做只读准备。
6. 原始用户视频只用于操作时序观察，不成为私聊算法夹具。合成、模拟器和真机分别记账；不能把本次本地通过写成这位测试者真机已通过。

## 子代理职责与发布

- **实现代理（GPT-6 Astra / high）：** 帧管线、严格恢复逻辑、两个采集适配器的生命周期与诊断值写入、算法和像素回归。
- **界面代理（GPT-6 Astra / high）：** 诊断模型新增字段、主应用等待与详情状态、中英文本地化及兼容性测试。与实现代理约定字段名，避免改同一文件。
- **发布代理（GPT-6 Astra / high）：** 起初只读核查本机归档／签名／上传方式与 Apple 当前版本状态，形成可执行发布步骤；主代理确认源码和实际验证完成后，递增版本、归档、审计、上传、等待 Apple 处理并关联现有 TestFlight 测试组、保存中英文说明和回执。明确区分上传成功、处理成功、内部可更新和外部 Beta 审核。
- **主代理：** 设计、审查实现与对抗边界、协调测试资源、维护实施状态与最终中文交付说明。

用户的“三次同一卡点失败即交接”规则适用于整个团队累计次数；切换工具、入口或代理不重置。每次失败立即向主代理报告，达到三次停止该任务，不后台重试或自动续跑。无关的既有工作区改动不得覆盖或纳入本次提交。

## 实施回填

实现、界面和发布准备均由用户指定的 GPT-6 Astra（high）子代理承担；主代理制定上述方案、做独立代码审查和真实模拟器手势验收。版本号与最终 Apple 状态以 [新版发布记录](release/0.1.6-testflight.md) 为准。

起步恢复已按统一验证器实现，正常匹配阈值未改。旧候选优先；备用经同样的区域／前景／歧义／重叠校验才可提升。稳定更新仍需三次稳定样本，但允许最多 0.25% 灰度像素发生变化、全帧平均差不超过 0.25 灰阶，差异位于不超过画面 10% 宽且 10% 高的局部框内；直接运动恢复不需要等到三次静止样本。每次与固定候选比较，不以逐帧累积相似容许持续漂移。

独立审查发现备用正文被严格判为 unchanged 时，顶部指示变化可能超过局部稳定限而覆盖最早目标图。实现已改为保留该目标候选，不发布长图、不积累稳定确认；随后非零位移仍须严格验证。这项修正保留了最早目标首屏的像素契约，并有专门回归，未调整期望像素掩盖差异。

已发布兜底与尚未可信的备用候选分开。备用提升写入失败时保持旧单屏；提升成功后当前帧渲染或首条正文事务失败时保持提升后的完整目标单屏。两采集适配器在事务异常后结束，不继续使用未落盘的匹配状态。正常运行的备用候选只有一张临时 PNG、一份灰度；替换、成功、异常、停止和析构清理。进程硬杀不能执行析构，可能残留临时孤儿，本轮没有跨会话扫描删除机制。

暂停只对已有连续内容要求找回旧重叠；仅有候选时仍可找新的目标起点。新增可选数值诊断与主界面等待提示，兼容旧会话；系统入口停止的主文案统一为“广播已结束”，详情解释也可能由用户手动停止。完整界面验证见 [启动状态与诊断界面记录](validation/2026-09-16-startup-ui.md)。

- 第一份原生构建源码已过期，且模拟器 availability 反复变化未进入测试，终止并保留日志。第二份最新源码全目标 109 项通过；没有把 `Resolve Package Graph` 日志本身当成已经查明的永久故障。
- 主代理第一份真实滚动运行编译了上述 unchanged 修正前的源码，因此主动中止；不把它算作最终验收或未修复产品故障的重复尝试，旧日志／结果保留。
- UI 保存首次失败是缺少专用模拟器照片添加权限，接着权限准备遇到设备已关机，按用户规则合并为同一卡点两次。根据已确认状态完成启动、等待就绪、授权后，保存与分享通过；没有第三次失败后继续尝试。
- 详情首次 UI 测试定位失败由实际 AX 层级证实是父 DisclosureGroup 标识覆盖子 ScrollView 标识，调整测试定位后通过。完整原失败结果保留，不覆盖原记录。
